# patch 0.1.4

এই প্যাচের সংশোধনগুলো `rockreyad/NARC-138-patch-0.1.4` branch-এর একই draft PR-এ জমবে। Linear-এর [patch 0.1.4 milestone](https://linear.app/narcdev/project/bari-khata-c6b283c05a95/issues?projectMilestoneId=f645b374-a06e-4592-b8ae-b349d97bac41)-এ প্রতিটি issue রাখুন। আরও সংশোধন ও শেষ যাচাইয়ের পরে এই PR দিয়ে `main`-এ নেওয়া হবে।

## অন্তর্ভুক্ত সংশোধন

- [NARC-138](https://linear.app/narcdev/issue/a0357438-33a2-4092-89c7-281bf23b8b96): খাতার মোট বাকির নিচে কার নামে কত টাকা বাকি দেখানো। নাম চাপলে এই খাতার সংশ্লিষ্ট লেনদেন খোলে; বিল ছাড়া শেষ কাজের পাওনা হলে ব্যক্তির কাজের হিসাব খোলে। নামহীন বিলের মূল রেকর্ড এবং কারও নামে না থাকা সমন্বয় আলাদা দেখা যায়। অন্য খাতার টাকা, অগ্রিম ও চলমান কাজের প্রতিশ্রুতি বর্তমান পাওনায় মেশে না।
- [NARC-141](https://linear.app/narcdev/issue/d8a0b551-a8e4-431c-82cb-4095e76c8724): লেনদেনে খোঁজা বা বাছাইয়ের সঙ্গে সব মেলা বিলের মোট খরচ দেখা যায়। ‘মাসে মাসে’ খুলে মাস বাছলে মোট ও নিচের তালিকা একই মাসের হয়; পুরোনো মাসও দেখা যায়। মিশ্র বিলের শুধু মেলা অংশ গোনা হয়, মূল বিল অক্ষত থাকে। বিলের টাকা দেওয়া আবার খরচ হয় না; মালের ফেরত খরচ থেকে বাদ যায়। তারিখহীন খরচ আলাদা দেখা যায়।

মালের নাম, ধরন বা আগের নামের সাজেশন বেছে হিসাব নির্দিষ্ট করা যায়। কাছাকাছি বানান নিজে থেকে টাকার হিসাবে মেশে না। শুধু নোট বা অন্য তথ্যে মেলা বিল তালিকায় থাকলেও খরচের মোটে বাদ থাকার কথা দেখায়। অনির্দিষ্ট মালের ফেরত বা আলাদা সমন্বয় অনুমান করে কোনো মালের নামে ভাগ হয় না।

খাতার ইতিমধ্যে লোড হওয়া তথ্য থেকে সূচি তৈরি হয়। খোঁজা, মাস বাছা ও ‘আরও দেখুন’-এ নতুন server বা IndexedDB query নেই। আরও ফল দেখানো বা সাজানোর সময় মোট আবার গণনা হয় না। তথ্যের কাঠামো বা সংরক্ষণের নিয়ম বদলায়নি।

## পরের সংশোধন যোগ করা

1. নতুন issue এই milestone-এ রাখুন। সংশোধনের commit এই patch branch-এ যোগ করুন, অথবা আলাদা branch-এর PR-এর base হিসেবে patch branch দিন।
2. অন্তর্ভুক্ত issue ও তার যাচাই এই নথি এবং সমন্বিত PR-এ হালনাগাদ করুন। একই প্যাচে সংশোধন যোগ করার সময় সংস্করণ `0.1.4` থাকবে।
3. সব সংশোধন শেষে চূড়ান্ত commit-এ `npm test`, `npm run build` ও `npm run release:check -- v0.1.4` চালান। প্রাসঙ্গিক পর্দা, তথ্য রেখে আবার খোলা ও ব্যাকআপ ফেরানো যাচাই করুন।
4. ব্যবহারকারীর প্রকাশের সিদ্ধান্তের পরে draft তুলে `main`-এ merge করুন। এরপর [রিলিজের নিয়ম](../RELEASING.md) অনুযায়ী সেই merge হওয়া commit-এ নতুন tag দিন।

## বর্তমান যাচাই

`npm test`-এ ২১০টি test file-এর ২,৭২৮টি পরীক্ষা সফল। `npm run build`, `npm run release:check -- v0.1.4`, Prettier ও `git diff --check` সফল। নামভিত্তিক বাকি, মিশ্র বিলের অংশ, ফেরত ও পরিশোধ আলাদা রাখা, সব ফল থেকে মোট, মাস ও অন্য বাছাই, তারিখহীন হিসাব, পয়সার পূর্ণসংখ্যার সীমা এবং বাংলা–ইংরেজি পর্দা যাচাই হয়েছে। IndexedDB-তে রেখে আবার খোলা ও ব্যাকআপ ফিরিয়েও খোঁজার মোট একই আছে। ব্রাউজারে ৩২০ ও ৩৯০ পিক্সেল প্রস্থে মাস বাছাই, বিল খোলা, ফিরে আসা ও পেজ আবার খোলা যাচাই হয়েছে।

স্থানীয় কৃত্রিম নমুনায় ৫০,০০০টি লাইনের সূচি একবার তৈরি করতে মধ্যম সময় প্রায় ২৩৯ ms, খোঁজার মোট করতে ৪১ ms এবং আগে তৈরি ফলের পরের অংশ দেখাতে ০.০০৪ ms লেগেছে। এটি M2 Pro ও Node 22-এর মাপ; ফোনের render সময়ের নিশ্চয়তা নয়। কোনো আসল খাতা বা আর্থিক ফাইল এই পরীক্ষায় ব্যবহার হয়নি।

## প্রকাশের অবস্থা

এটি সংশোধন জমা করার প্যাচ। `main`-এ merge, `v0.1.4` tag ও release করা হয়নি। আগে খোলা [PR #41](https://github.com/rockreyad/bari-khata/pull/41)-এর ফোনে পুরোনো খাতা খোলার সংশোধন এই branch-এ এখনও আনা হয়নি; সেটির পর্যালোচনা ও একত্র করার সিদ্ধান্ত আলাদা থাকবে। ব্যক্তিগত হিসাব বা ভাউচার এই নথি ও PR-এ থাকবে না।
