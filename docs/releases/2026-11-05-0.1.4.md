# 0.1.4: পুরোনো ভাউচারসহ খাতা খোলার সংশোধন

0.1.3 আপডেটের পরে একটি Android device-এ «খাতা পড়া যাচ্ছে না» পর্দা দেখা যায়; retry ও পুনরায় install করেও খোলেনি। ব্যবহারকারী জানান iPhone-এ আপডেট স্বাভাবিক ছিল এবং Android-এর site storage মুছে দেওয়ার পরে আবার খোলা গেছে। মুছে ফেলা device-এর মূল তথ্য আর পরীক্ষা করা সম্ভব নয়, তাই সেই device-এর নির্দিষ্ট কারণ নিশ্চিত বলা হচ্ছে না।

কোডে একই ব্যর্থতা ঘটানোর একটি কারণ পাওয়া গেছে: ভাউচার যোগ করলে IndexedDB-তে native `File` রাখা হয়, কিন্তু migration-এর যাচাই শুধু `[object Blob]` গ্রহণ করত। `File` বৈধ `Blob` হলেও তার tag আলাদা। স্থানীয় `File` থাকলে upgrade transaction বাতিল হতো; cloud থেকে নামানো `Blob` থাকলে একই বাধা থাকত না।

## সংশোধন

- আসল `Blob` ও `File` গ্রহণ করা হয়। অন্য window-এর ভাউচারও গ্রহণযোগ্য; শুধু tag বা পদ্ধতির নাম নকল করা object গ্রহণযোগ্য নয়। আগের MIME, মাপ, মালিকানা ও reference যাচাই বহাল।
- খাতা খোলার error পর্দাতেও বিদ্যমান «নতুন আপডেট এসেছে» ব্যবস্থা চলে। ব্যবহারকারীর ইচ্ছা ছাড়া reload হয় না; অসমাপ্ত form-এর সুরক্ষা বহাল।
- নতুন SQL migration, হিসাবের নিয়ম পরিবর্তন বা স্থানীয় তথ্য মোছার ব্যবস্থা নেই। আগের migration ব্যর্থ হলে রাখা মূল খাতা থেকেই আবার চেষ্টা হয়।

## যাচাই ও সীমা

Native `File`-এর সরাসরি regression দরকার: Node-এর `structuredClone` এবং `fake-indexeddb` সেটিকে `Blob` বানিয়ে ফেলতে পারে। তাই unit test-এর সঙ্গে আলাদা browser-এ নমুনা IndexedDB থেকে upgrade, বন্ধ করে আবার খোলা, ভাউচারের bytes এবং অসমাপ্ত লেখা/পাঠানো বাকি তথ্য অক্ষত থাকার পরীক্ষা করুন। কোনো আসল খাতায় পরীক্ষার তথ্য যোগ করবেন না।

৫ নভেম্বর ২০২৬-এ স্থানীয় যাচাইয়ে **২০৭টি file-এর ২৬৭৭টি পরীক্ষা সফল**; build ও formatting check-ও সফল। আলাদা Chrome browser-এর native IndexedDB পরীক্ষায় `File`-সহ পুরোনো যাচাইয়ের ব্যর্থতা পুনরায় ঘটেছে; upgrade বাতিল হওয়ার পর মূল তথ্য অক্ষত ছিল। সংশোধিত v1→v4 upgrade এবং বন্ধ করে আবার খোলা সফল হয়েছে: ভাউচারের bytes, নাম, MIME, মাপ ও `lastModified`, মূল খাতার archive, হিসাব, draft-এর `File` এবং frozen outbox অপরিবর্তিত। পরীক্ষাটি শুধু বানানো তথ্য ব্যবহার করেছে; এটি মুছে ফেলা Android storage-এর forensic যাচাই নয়।

```sh
npm test
npm run build
npm run release:check -- v0.1.4
```

ভবিষ্যতে এমন সমস্যা হলে site data মুছে ফেলা বা uninstall সমাধান হিসেবে বলবেন না। তাতে অনলাইনে না যাওয়া হিসাব হারাতে পারে। আগে মূল স্থানীয় তথ্য রাখুন, ব্যর্থতার কারণ ঠিক করুন, তারপর একই তথ্য দিয়ে upgrade যাচাই করুন। 0.1.3-এর error পর্দায় update notice নেই; নতুন সংস্করণ পাওয়া গেলে app ও একই সাইটের সব tab বন্ধ করে আবার খোলার প্রয়োজন হতে পারে।
