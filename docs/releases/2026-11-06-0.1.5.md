# patch 0.1.5

এই প্যাচের কাজ [NARC-151](https://linear.app/narcdev/issue/NARC-151)-এ রাখা হয়েছে।

শেয়ার করা হিসাবের পাতায় মিস্ত্রি ও দোকানদারের জন্য পাওয়া টাকা ও বাকি পাওনা সহজে দেখার সংশোধন। `package.json` ও `package-lock.json`-এর সংস্করণ `0.1.5`; release tag হবে `v0.1.5`।

## কী বদলেছে

- সারাংশ, কাজের কার্ড ও মাসের চার্ট অ্যাপের নির্বাচিত থিমের রং মানে। ছোট পর্দায় অঙ্ক ভেঙে যাওয়া, বাড়তি ফাঁকা জায়গা ও অপ্রয়োজনীয় লেখা কমানো হয়েছে।
- কাজের কার্ড এক সারিতে সোয়াইপ করে দেখা যায়। চুক্তির মোট, পাওয়া টাকা, আর পাওয়ার অঙ্ক ও মূল খাতায় লেখা কাজের অবস্থা সরাসরি থাকে; এগুলো দেখতে আলাদা বিস্তারিত খুলতে হয় না।
- চলছে এমন কাজ আগে আসে। চলমান ও অন্য কাজের প্রতিটি দলের মধ্যে চুক্তির মোট টাকা বেশি হলে সেটি সামনে থাকে; সমান হলে আগের ক্রম বজায় থাকে।
- মাসের লাইন চার্টে আসলে পাওয়া টাকা দেখা যায়। মাস বেছে অঙ্ক দেখা যায়; ফেরত টাকা ও তারিখ ছাড়া টাকা আলাদা থাকে। সার্চ বা লেনদেনের পাতা বদলালেও পুরো পরিসরের মাসের হিসাব বদলায় না।
- চার্ট সম্পূর্ণ তথ্য, একই শেয়ারের পরিসর ও সংস্করণ যাচাই করে। বিল বা নগদ নয় এমন সমন্বয়কে পাওয়া টাকা ধরা হয় না। সারাংশে সমন্বিত অঙ্ক ও চুক্তিতে অর্জিত পাওনার আগের হিসাব বহাল থাকে।

## সার্ভারের পরিবর্তন

`supabase/migrations/202611060003_shared_contract_status.sql` শেয়ার করা চুক্তির উত্তরে মূল খাতার `status` যোগ করে। এটি বিদ্যমান function-এর প্রকাশ্য চুক্তির অংশে শুধু অবস্থাটি যোগ করে; টাকার হিসাব, পরিসর ও অনুমতি বদলায় না। প্রত্যাশিত কাঠামো না পেলে migration থামে। আবার চালালে একই পরিবর্তন পুনরায় যোগ হয় না।

আগে প্রয়োগ করা migration দেখে এই SQL প্রয়োগ করতে হবে। অ্যাপের build নিজে SQL চালায় না। নতুন সার্ভার থেকে অবস্থা না এলে client সেটি পাওয়া যায়নি বলে দেখায়; খাতায় অবস্থা লেখা না থাকলে সেটিও স্পষ্ট থাকে। টাকার অঙ্ক দেখে কাজ শেষ ধরে নেওয়া হয় না।

এই প্যাচের জন্য `release-policy.json` বা backend-এর সর্বনিম্ন সংস্করণ বাড়ানো হয়নি; দুটিতেই `0.1.4` বহাল। প্রকাশে IndexedDB, খসড়া, পাঠানো বাকি হিসাব বা login তথ্য মোছার দরকার নেই।

## যাচাই ও প্রকাশ

```sh
npm test
npm run build
npm run release:check -- v0.1.5
./node_modules/.bin/tsx scripts/backend-shared-contract-status-check.ts
```

Backend পরীক্ষাটি শুধু স্থানীয় Bari-Khata Docker database-এ নমুনা তথ্য ব্যবহার করে। কাজের অবস্থা, আগের টাকার হিসাব, শেয়ারের পরিসর, গোপনীয়তা ও function-এর অনুমতি যাচাইয়ের পর সব পরিবর্তন rollback হয়। মোবাইলে কার্ডের ক্রম, সোয়াইপ, সরাসরি মোট ও অবস্থা এবং মাস বেছে চার্টের অঙ্ক দেখাও যাচাই করতে হবে।

`main`-এ pull request-এর `verify` সফল হওয়ার পরে squash merge করতে হবে। merge হওয়া `0.1.5` commit-এ `v0.1.5` tag দিলে `Release` workflow আবার সংস্করণ, পরীক্ষা ও build যাচাই করে GitHub Release প্রকাশ করে। Hosting deployment, `/release.json` ও কাজের অবস্থা আলাদাভাবে যাচাই করতে হবে। বিস্তারিত [রিলিজের নিয়মে](../RELEASING.md) আছে।
